# Detect Voids 평가 (Evaluate)

손으로 마킹한 보이드와 자동 검출 결과를 비교해 **놓친 것·잘못 잡은 것·크기 차이의 원인**을 짧은 코드로 보여 줍니다.
현장 PC에서 파일을 옮길 수 없을 때 화면의 코드를 읽고 휴대폰으로 **그대로 입력해** 보내면 됩니다. 코드는 영문자, 숫자, 점, 띄어쓰기만 씁니다.

## 1. 사용법

1. 파일을 열고 그리드·bbox·본딩맵을 맞춥니다(Detect Voids와 같은 조건).
2. 정답이 될 보이드를 **손으로 마킹**합니다(또는 검토를 마친 voids.json을 불러옵니다).
   - 불러온 레이어 범위의 마킹만 비교합니다.
   - 점선(검출 후 검토하지 않은 것)과 bbox는 정답에서 뺍니다. 검출된 것도 한 번 손대면(이동·크기·타입) 정답으로 칩니다.
   - 일부 칩만 마킹했다면 마킹하지 않은 칩의 검출은 모두 "잘못 잡음"으로 셉니다. 비교할 칩은 빠짐없이 마킹하세요.
3. Void Marking 패널에서 Method와 Thr을 고르고 **Evaluate**를 누릅니다. 마킹은 바뀌지 않습니다.
4. 창에 코드가 크게 나옵니다.
   - **Copy**: 클립보드로 복사
   - **Open Report**: 표와 칩 이미지가 있는 report.html
   - 결과 폴더: `사용자 폴더\TIF_Viewer_eval\<파일이름>_<시각>\` (report.html, eval.json, summary.txt, img\)

## 2. 코드 읽는 법

예:

```
VD1 dd rf t6 f8 w256 m8 c412 b100 L0to11 h47
T ok31 ly3 ms13 fp9 R66 P72
L0 h9 ok8 ms1 fp2 bt1 pk.6 n412 s1.2 r.9 a3 x.7
L11 h12 ok1 ms11 bt8 dup3 pk.3 n412 s2.8 r2.1 a4 x1.4
M bt9 op4 dup3
B pk.6 s1.9 c2.1 g.05 z4
F ed3 le2 ot4
S w.62 h.58 hf.85 lt12 gt2
Y25
```

값이 0인 항목은 생략합니다. 소수는 앞의 0을 뺍니다(.6 = 0.6). 값이 없으면 na. 각 항목은 영문 약자 + 숫자입니다.

### 첫 줄: 조건

| 항목 | 뜻 |
|---|---|
| `VD1` | 코드 형식 버전 |
| `dd` / `pcm` / `pcr` | Die-to-die / PatchCore MobileNetV2 / PatchCore ResNet50 |
| `rf` / `rs` / `rl` | 여러 레이어에서 잡힌 자리를 마킹할 레이어: 처음(first) / 가장 강한 곳(strongest) / 마지막(last) |
| `t` | 임계값 (Thr) |
| `f` | 축소 배율: 작업 이미지 1픽셀 = 원본 f픽셀 |
| `w` | 작업 이미지 긴 변 (work_size) |
| `m` | min_size_px |
| `c` | 검사한 칸 수 |
| `b` | 기준 bbox가 있는 칸 비율(%). 낮으면 칩을 그리드 칸으로 맞춰 정렬이 거칠어짐 |
| `L` | 평가한 레이어 범위 (`L0to11` = 0~11) |
| `h` | 손 마킹 수(정답) |

### `T`: 전체

| 항목 | 뜻 |
|---|---|
| `ok` | 같은 레이어에서 찾음 |
| `ly` | 같은 자리를 다른 레이어에서 찾음 (레이어 판정 차이) |
| `ms` | 놓침 |
| `fp` | 손 마킹이 없는 곳을 잡음 |
| `R` | 재현율 % = ok / h (손 마킹이 없으면 생략) |
| `P` | 정밀도 % = ok / 검출 수 (검출이 없으면 생략) |

### `L<번호>`: 레이어별

앞쪽: 그 레이어의 h, ok, ly, ms, fp와 놓친 이유별 개수, `pk`(임계값 미달로 놓친 것의 최대 편차 / 임계값, 중앙값).

`n`부터: 칩 상태

| 항목 | 뜻 |
|---|---|
| `n` | 칩 수 |
| `s` | 칩 간 편차(spread) 중앙값. 크면 칩마다 많이 달라 둔감해짐 |
| `r` | 밝기·음영 보정 후 칩과 기준 칩의 차이 중앙값. 크면 보정이 잘 안 맞음 |
| `a` | 기준 칩 대비 칩 위치 어긋남(원본 px, 중앙값). bbox 정렬 상태 |
| `x` | 칩마다 최대 편차 / 임계값의 중앙값. 1 이상이면 보통 칩도 임계값을 넘는 곳이 있음(과검 위험) |

### `D`: 다른 레이어에서 찾은 것 (`ly`)

`L11to0n20` = 손 마킹은 11번 레이어인데 0번 레이어에 마킹됨, 20개. 많은 순서로 최대 6개.
한쪽으로 몰려 있으면 Void Marking의 **Mark on layer**(처음 / 가장 강한 곳 / 마지막)를 바꿔 보세요.

### `M`: 놓친 이유 (먼저 해당하는 것)

| 코드 | 뜻 | 대처 |
|---|---|---|
| `nl` | 그 레이어를 평가하지 못함 (안 불러옴, 칩 3개 미만) | 레이어 범위 확인 |
| `ni` | 그 칸을 검사하지 않음 (본딩맵 제외 LEG) | 본딩맵 확인 |
| `mg` | 다른 손 마킹과 한 덩어리로 잡힘 | 가까운 보이드 병합 거리 |
| `dup` | 같은 자리를 다른 레이어에 마킹하기로 해서 건너뜀 (Mark on layer 규칙) | Mark on layer, 다른 레이어의 과검 확인 |
| `lg` | 덩어리가 너무 큼 (max_area_frac 초과: 칩 불량·정렬 실패로 봄) | |
| `sm` | 덩어리가 너무 작음 (min_size_px 미만) | min_size_px |
| `op` | 임계값은 넘었지만 3x3 열림 연산에서 지워짐 (가늘거나 작음, 레이아웃 선 위) | 작업 해상도(work_size) |
| `bt` | 편차가 임계값 미달 | 아래 `B` 참고 |

### `B`: 임계값 미달(`bt`)로 놓친 것의 중앙값

| 항목 | 뜻 |
|---|---|
| `pk` | 최대 편차 / 임계값. 0.8~1이면 임계값을 조금 낮추면 잡힘, 0.3 이하면 이 방법으로 안 보임 |
| `s` | 그 자리의 칩 간 편차 / 레이어 중앙값. 2 이상이면 레이아웃 경계 등 원래 흔들리는 자리 |
| `c` | 기준 칩과의 밝기 차 (칩 MAD 단위). 작으면 대비가 낮은 보이드 |
| `g` | 같은 자리가 튀는 칩 비율. 크면 보이드가 여러 칩에 흔해 기준 칩에 흡수됨 |
| `z` | 손 마킹 크기 (작업 픽셀). 3 이하면 해상도 한계 |

### `F`: 잘못 잡은 것의 종류

| 코드 | 뜻 |
|---|---|
| `ed` | 칩 가장자리에 닿음 (bbox·정렬) |
| `al` | 그 칩이 기준 칩보다 1.5 작업 픽셀 이상 어긋남 |
| `lg` | 큰 덩어리 (칩의 2% 초과) |
| `le` | 레이아웃 경계 (칩 간 편차가 레이어 중앙값의 2배 초과) |
| `cm` | 많은 칩(15% 초과)이 같이 튀는 자리 |
| `ot` | 그 밖 (마킹하지 않은 실제 보이드일 수도 있음) |

### `S`: 크기 (찾은 것만)

| 항목 | 뜻 |
|---|---|
| `w`, `h` | 검출 폭·높이 / 손 마킹 폭·높이 (중앙값) |
| `hf` | 임계값의 절반에서 잰 폭 / 손 마킹 폭. 이 값이 1에 가깝고 `w`가 작으면 임계값 때문에 가장자리가 잘림 |
| `lt`, `gt` | 0.7배보다 작게 / 1.4배보다 크게 잡힌 수 |

### `Y`: 타입

자동 타입(type_rules)이 손 마킹 타입과 같은 수 (찾은 수는 `T`의 ok).

## 3. 보고서 (report.html)

- 레이어 표, 놓친 것·잘못 잡은 것·다른 레이어·크기 표. 각 행의 view로 칩 이미지로 갑니다.
- 칩 이미지 패널: 칩(보정 후), 기준(golden) 칩, 편차 지도(0 ~ 임계값 2배), 마스크(회색: 임계값 초과, 흰색: 열림 연산 후).
- 상자 색: 초록 = 손 마킹, 빨강 = 검출, 주황 = 너무 작음, 보라 = 너무 큼, 파랑 = 위 레이어 규칙으로 건너뜀.
- 레이어별 기준 칩(golden)과 칩 간 편차 지도(spread)도 링크됩니다.
